# 电机振动故障检测：数据采集操作手册

这份手册面向没有参与项目开发的操作者。按照顺序执行即可完成一次调试采集或正式数据采集。

## 1. 先了解采集结果

每次运行 `recv.py` 会接收若干个数据帧。当前默认每帧 1024 点、采样率约 1 kHz，建议一次采集 20 帧。

| 采集类型 | 命令参数 | 保存位置 | 是否进入训练清单 |
| --- | --- | --- | --- |
| 调试 | `--data-role debug` | `04_数据集/debug_raw/` | 否 |
| 自检/校准 | `--data-role selftest` 或 `calibration` | `04_数据集/debug_raw/` | 否 |
| 正式 | `--data-role formal` | `04_数据集/formal/` | 是，先标记为 `pending` |

旧版 `04_数据集/raw/` 只保存历史文件，新采集不会再写入那里。

项目固定轴向为：X 轴是振动测量轴，Y 轴是重力轴。采集程序会检查收到的轴号；如果不是 X 轴，文件不会通过最终元数据校验。

## 2. 开始前准备

### 2.1 硬件与现场

1. 一次只运行一台风扇。
2. 传感器贴在约定测点，方向保持一致。
3. 建议制作一块刚性底板：用风扇框架原有安装孔、M4 螺栓、平垫圈和防松螺母把风扇固定在木板或厚亚克力板上，再用两个 C 形夹把底板夹紧在桌面。传感器固定在风扇框架上，不贴在底板上。
4. 给风扇安装紧固点编号 `M1`、`M2`……。正常和不平衡工况全部紧固；机械松动只回退指定紧固点，底板与桌面的夹紧状态不变。
5. 贴胶带、改变电压或改变紧固点状态前，先确定上一段采集已经结束。
6. 不使用橡皮筋、软泡棉或可移动的压重物作为正式夹具；它们会改变支撑刚度或让整机滑移，造成无法解释的标签混杂。
7. 风扇叶片应有防护罩。松动紧固件仍须保留足够螺纹啮合，不得接近脱落；一旦出现整机位移、叶片擦碰或紧固件继续自行旋出，立即断电并废弃该段数据。

### 2.2 软件与串口

在 PowerShell 中进入项目根目录：

```powershell
Set-Location 'C:\Work\嵌入式练习\练习工程项目\实践项目-电机振动故障检测'
```

设置 Python 和串口变量。下面假定 Python 环境已经安装 `numpy`、`pyserial` 和 `matplotlib`：

```powershell
$Python = 'C:\Users\lyl\miniconda3\python.exe'
$Port = 'COM13'
& $Python -c "import numpy, serial, matplotlib; print('Python 依赖正常')"
```

如果你的 Python 路径不同，只修改 `$Python`；如果开发板不是 COM13，只修改 `$Port`。

不知道串口号时，可以先查询当前串口：

```powershell
Get-CimInstance Win32_SerialPort | Select-Object DeviceID, Name
```

把查询结果中的 `COMxx` 填入 `$Port`。

开始采集前必须：

- 关闭串口助手和其他可能占用该串口的软件；
- 确认开发板已烧录当前固件并能正常发送数据帧；
- 确认风扇已经接通电源并稳定运行；
- 确认本次电压值。没有测速设备时，`--rpm-measured` 可以不填，但应填写 `--voltage-set-v`，有万用表时再填写 `--voltage-measured-v`。

## 3. 标签怎么填写

| 参数 | 填写规则 |
| --- | --- |
| `--device-id` | 给每台风扇固定编号，例如 `fanA`、`fanB`；同一台风扇始终使用同一编号 |
| `--session-id` | 同一夹具、传感器位置和连续实验使用同一个会话编号；计划内的基线/故障切换可沿用，夹具或测点意外变化后必须新建会话 |
| `--run-index` | 同一会话中的第几段，从 1、2、3 递增 |
| `--observed-condition` | `baseline` 正常无故障；`added_mass` 贴胶带；`mount_looseness` 安装固定处松动；`unknown` 未知/仅调试 |
| `--label-basis` | 正常基线、贴胶带和受控松动均用 `controlled_injection` |
| `--label-confidence` | 操作与记录都可确认时用 `confirmed`；无法确认时不要作为正式数据 |
| `--voltage-set-v` | 电源设定电压，必填，例如 `9` |
| `--voltage-measured-v` | 实测电压，可选 |
| `--fault-level` | 正常填 `0`；贴胶带按实验等级填 `1`、`2`、`3`；同一紧固点/方法下建议回退 1/4 圈=`1`、1/2 圈=`2` |
| `--tape-count` | 贴胶带数量；正常填 `0`，一片填 `1`，两片填 `2` |
| `--tape-mass-mg`、`--tape-radius-mm`、`--tape-angle-deg` | 已知时填写，未知可留空 |
| `--loose-fastener-id` | 松动的安装紧固点编号，例如 `M1`；机械松动必填 |
| `--loosen-turns` | 从全部紧固的基准位置回退多少圈，例如 `0.25` 或 `0.5` |
| `--mount-gap-mm` | 若用定厚垫片制造间隙，填写间隙毫米数；与回退圈数至少填一项 |
| `--notes` | 记录电源档位、固定异常、风扇缓慢位移等影响解释的情况 |

不需要手工填写 `--target-label`：程序会根据客观工况自动映射，并拒绝与下表不一致的手工覆盖：

```text
baseline       → normal
added_mass     → unbalance
mount_looseness → looseness
unknown        → unassigned
```

采集表单不包含夹具版本、传感器编号、传感器安装点。

## 4. 调试采集

调试采集不会写入 `manifest.csv`，适合确认串口、轴向、帧数、频谱和固定方式。

### 4.1 调试一段正常风扇数据

```powershell
& $Python .\03_Python工具\recv.py `
  --port $Port `
  --data-role debug `
  --device-id fanA `
  --session-id fanA_debug_20260924 `
  --run-index 1 `
  --observed-condition unknown `
  --label-basis unknown `
  --label-confidence unknown `
  --voltage-set-v 9 `
  --frames 20 `
  --notes '调试：检查串口、X轴和固定方式'
```

### 4.2 调试贴一片胶带

```powershell
& $Python .\03_Python工具\recv.py `
  --port $Port `
  --data-role debug `
  --device-id fanA `
  --session-id fanA_debug_tape `
  --run-index 1 `
  --observed-condition added_mass `
  --label-basis controlled_injection `
  --label-confidence confirmed `
  --fault-level 1 `
  --fault-method tape_mass `
  --tape-spec-id tape01 `
  --tape-count 1 `
  --voltage-set-v 9 `
  --frames 20 `
  --notes '调试：一片胶带'
```

调试阶段可以先只采 5 帧，把命令最后的 `--frames 20` 改成 `--frames 5`，确认链路正常后再采 20 帧。

## 5. 正式数据采集

正式采集与调试采集的命令基本相同，关键切换是：

```text
--data-role debug   →   --data-role formal
```

正式采集还必须填写明确的客观工况、标签依据和可信度。每一种工况、每一个电压、每一台风扇建议单独采集一组段，并递增 `--run-index`。

### 5.1 正常基线（无胶带）

```powershell
& $Python .\03_Python工具\recv.py `
  --port $Port `
  --data-role formal `
  --device-id fanA `
  --session-id fanA_baseline_9V `
  --run-index 1 `
  --observed-condition baseline `
  --label-basis controlled_injection `
  --label-confidence confirmed `
  --fault-level 0 `
  --tape-count 0 `
  --voltage-set-v 9 `
  --frames 20 `
  --notes '正常基线，无胶带'
```

### 5.2 一片胶带：不平衡等级 1

```powershell
& $Python .\03_Python工具\recv.py `
  --port $Port `
  --data-role formal `
  --device-id fanA `
  --session-id fanA_unbalance_9V `
  --run-index 1 `
  --observed-condition added_mass `
  --label-basis controlled_injection `
  --label-confidence confirmed `
  --fault-level 1 `
  --fault-method tape_mass `
  --tape-spec-id tape01 `
  --tape-count 1 `
  --tape-mass-mg 120 `
  --tape-radius-mm 28 `
  --tape-angle-deg 0 `
  --voltage-set-v 9 `
  --frames 20 `
  --notes '一片胶带；质量和位置按实测修改'
```

### 5.3 两片胶带：不平衡等级 2

```powershell
& $Python .\03_Python工具\recv.py `
  --port $Port `
  --data-role formal `
  --device-id fanA `
  --session-id fanA_unbalance_9V `
  --run-index 2 `
  --observed-condition added_mass `
  --label-basis controlled_injection `
  --label-confidence confirmed `
  --fault-level 2 `
  --fault-method tape_mass `
  --tape-spec-id tape01 `
  --tape-count 2 `
  --tape-mass-mg 240 `
  --tape-radius-mm 28 `
  --tape-angle-deg 0 `
  --voltage-set-v 9 `
  --frames 20 `
  --notes '两片胶带；风扇若发生位移先停止并重新固定'
```

两片胶带如果让风扇在桌面缓慢移动，不要把这一段直接混入正式训练集。先重新固定；如果固定方式确实发生变化，使用新的 `session-id`。

### 5.4 安装固定处机械松动

先在全部紧固状态下采正常基线。随后只改变一个有编号的安装紧固点，建议先做 `M1` 回退 1/4 圈；如果整机没有位移、碰擦或紧固件自行旋出，再试 1/2 圈。不要松开底板与桌面的 C 形夹。

```powershell
& $Python .\03_Python工具\recv.py `
  --port $Port `
  --data-role formal `
  --device-id fanA `
  --session-id fanA_looseness_9V `
  --run-index 1 `
  --observed-condition mount_looseness `
  --label-basis controlled_injection `
  --label-confidence confirmed `
  --fault-level 1 `
  --fault-method fastener_backoff `
  --loose-fastener-id M1 `
  --loosen-turns 0.25 `
  --voltage-set-v 9 `
  --frames 20 `
  --notes 'M1 从基准紧固位置回退 1/4 圈；底板夹紧不变'
```

同一个 `session-id` 内应交替采集“全部紧固基线 → M1 回退 1/4 圈 → 恢复紧固基线”，至少重复 3 轮。恢复后的频谱若不能回到基线附近，应先排查夹具或安装位置变化，不要把该轮直接纳入正式训练集。若采用定厚垫片制造间隙，把 `--fault-method` 改为 `shim_gap` 并填写 `--mount-gap-mm`。

### 5.5 自检或校准数据

自检数据只用于检查链路，不用于训练：

```powershell
& $Python .\03_Python工具\recv.py `
  --port $Port `
  --data-role selftest `
  --device-id board01 `
  --session-id board_selftest_20260924 `
  --run-index 1 `
  --observed-condition unknown `
  --label-basis unknown `
  --label-confidence unknown `
  --voltage-set-v 9 `
  --frames 5 `
  --notes '板上桩信号或链路自检'
```

## 6. 采集结束后的检查

`recv.py` 结束时会打印 CSV 路径。优先复制这条路径，不要凭“最新文件”猜测记录。

假设路径保存在 PowerShell 变量 `$Csv` 中：

```powershell
$Csv = 'C:\Work\嵌入式练习\练习工程项目\实践项目-电机振动故障检测\04_数据集\formal\这里替换为实际文件名.csv'
& $Python .\03_Python工具\check_raw.py $Csv
& $Python .\03_Python工具\plot_check.py $Csv
& $Python .\03_Python工具\peak_check.py $Csv
& $Python .\03_Python工具\harmonics.py $Csv
```

重点检查：

- 收到的轴是否为 X；
- 丢帧数是否为 0；
- 频谱是否有合理的主峰；
- 正常、贴一片、贴两片、机械松动之间是否有可解释变化；
- 风扇是否在采集期间发生位移；
- 松动后恢复紧固的复测是否回到基线附近；
- 电压和备注是否与实际操作一致。

正式文件进入 `manifest.csv` 后，`quality_status` 初始为 `pending`。检查完成后，用 Excel、VS Code 或其他表格工具打开 `04_数据集/manifest.csv`：

- 数据正常、标签和工况可信：把该行改为 `quality_status=pass`；
- 数据有丢帧、位移、串口异常或标签不确定：改为 `quality_status=reject`，并在 `quality_reason` 写原因；
- 暂时无法判断：保持 `pending`，不要训练。

## 7. 生成训练划分

至少有两台设备并完成质检后，按设备留出测试集：

```powershell
& $Python .\03_Python工具\make_dataset.py `
  --test-device fanB
```

如果测试设备不是 `fanB`，替换成实际编号。生成结果位于 `04_数据集/processed/`，包括：

- `split_manifest.csv`：训练/测试划分；
- `summary.json`：筛选、排除和设备划分统计。

脚本默认只使用 schema v3、`data_role=formal`、`quality_status=pass`、有明确模型标签且不是 `suspect` 的记录。

## 8. 常见问题

### 串口打开失败

- 关闭串口助手；
- 确认 `$Port` 与设备管理器一致；
- 确认开发板 USB 已连接；
- 不要同时运行两个 `recv.py`。

### 提示标签校验失败

- `formal` 不能使用 `observed-condition unknown`；
- `formal` 必须填写 `label-basis` 和 `label-confidence`；
- `added_mass` 必须填写 `--fault-level >= 1` 和 `--tape-count >= 1`；
- `mount_looseness` 必须填写 `--fault-level >= 1`、`--fault-method`、`--loose-fastener-id`，以及 `--loosen-turns > 0` 或 `--mount-gap-mm > 0`；
- 真实设备必须填写 `--voltage-set-v`。

### 收到的不是 X 轴

停止使用该段数据，检查固件当前发送轴和传感器方向。不要把 Z/Y 轴文件改名伪装成 X 轴。

### 想从正式切回调试

保留设备、工况和电压参数，只把：

```text
--data-role formal
```

改成：

```text
--data-role debug
```

调试文件不会写入正式 `manifest.csv`，适合先验证设置，再复制参数进行正式采集。
