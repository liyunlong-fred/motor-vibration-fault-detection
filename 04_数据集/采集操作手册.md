# 电机振动故障检测：统一采集窗口操作手册

本手册说明 `capture_and_analyze.py` 窗口中的每个标签、什么时候填写什么值，以及正式数据如何质检。它替代早期“手工拼接多段 PowerShell 参数，再逐个运行分析脚本”的日常流程；`recv.py` 和独立分析脚本仍保留给排障和开发使用。

从项目根目录启动窗口：

```powershell
& .\.conda\python.exe .\03_Python工具\capture_and_analyze.py
```

操作顺序是：填写事实性信息 → 确认硬件已准备 → 自动接收指定帧数 → 自动分析**本次刚生成的 CSV** → 人工质检。采集期间不要改变电压、胶带、紧固状态、夹具或传感器位置。

## 1. 采集前准备

1. 一次只运行一台风扇；传感器固定在约定测点，方向不可改变。
2. 风扇框架应通过刚性底板、螺栓和 C 形夹固定到桌面。传感器贴在风扇框架，不贴在底板。
3. 给风扇安装紧固点编号，例如 `M1`、`M2`。正常与不平衡工况全部紧固；松动工况只改变一个已编号的紧固点，底板与桌面的夹紧状态始终不变。
4. 不把橡皮筋、软泡棉、可移动压重物或整机在桌面滑移当作正式松动工况。出现整机位移、叶片擦碰或紧固件继续自行旋出时，立即断电并废弃该段数据。
5. 关闭串口助手及其他占用开发板串口的软件。默认串口为 `COM17`、波特率为 `460800`；不知道端口时可执行：

   ```powershell
   Get-CimInstance Win32_SerialPort | Select-Object DeviceID, Name
   ```

6. 正式采集前复位开发板，确认固件启动信息为 `capture=fifo_continuous fs=1000 N=1024`；确认风扇已通电且稳定运行。

当前每帧为 1024 个 X 轴原始 `int16` 点，采样率配置为 1 kHz。默认 20 帧即 20,480 点、名义 20.48 秒；名义时长不是墙钟实测值。

## 2. 页面一：基本信息

| 窗口标签 | 含义与填写样式 | 必填规则 |
| --- | --- | --- |
| 采集模式 | 选择本段数据的用途，见下表。 | 必填 |
| 数据来源 | `real` 表示真实硬件；`synthetic` 只用于可追溯的软件/桩信号，不能把真实风扇数据标为 synthetic。 | 必填 |
| 串口 | Windows 设备号，例如 `COM17`。窗口和 `recv.py` 的默认值均为 `COM17`，实际端口不同时必须改为设备管理器显示的值。 | 必填 |
| 波特率 | 与烧录固件一致，当前为 `460800`。 | 必填 |
| 采集帧数 | 要接收的 1024 点窗口数。调试通常填 `5`，常规采集填 `20`；必须是正整数。 | 必填 |
| 设备编号 | 被测风扇的稳定编号，例如 `fanA`、`fanB`。同一物理风扇始终使用同一编号。 | 必填 |
| 设备类型 | 当前通常填 `fan`。 | 建议填写 |
| 会话编号 | 一段采集条件不变的连续实验区段的共同名称。窗口默认预填 `fanA_rig01_9V_20260928`；详细规则见下一节。 | formal 建议必填 |
| 本会话运行序号 | 同一会话内某一段采集的顺序号，从 `1` 递增；详细规则见下一节。 | 必填 |
| 设定电压 V | 电源设定值，例如 `6`、`9`、`12`。 | 真实设备必填 |
| 实测电压 V | 万用表读数，例如 `8.96`；没有测量可留空。 | 可选 |
| 实测转速 RPM | 独立 TACH 或转速计读数，例如 `3061`；没有同步测速可留空。 | 可选 |

窗口还会预填当前可安全复用的常用值：设备编号 `fanA`、设备类型 `fan`、夹具编号 `rig01`、传感器模块 `mpu01`、传感器测点 `fan_frame_top_left`、安装姿态 `x_measure_y_gravity`、波特率 `460800`、帧数 `20`、设定电压 `9`、运行序号 `1` 和标定记录 `uncalibrated`。这些只是当前固定工装的起始值；若模块、测点或姿态与现场不一致，必须先改正。重力参考符号和实际固件构建号仍须按本次事实填写。

### 会话编号与本会话运行序号：用来回答“同一轮实验中的第几段？”

这两个字段不是故障标签，也不描述帧数。它们把同一轮可比较的实验段串起来，避免后续训练、质检或复盘时把“夹具换了/电压变了”的影响误当作故障差异。

```text
会话编号（实验边界）              本会话运行序号（段落顺序）
fanA_rig01_9V_20260928_a          1, 2, 3, 4, ...
        │                                  │
        └── 同一套可比条件的一轮实验       └── 该轮中的第几次保存
```

#### 1. 会话编号是什么

会话编号（`session_id`）是“一段连续且采集条件不变的实验区段”的共同 ID，不是每个 CSV 的唯一文件名。一个会话内的各段应使用同一个会话编号，前提是下面这些条件都没有改变：

- 同一台被测设备（例如始终是 `fanA`）；
- 同一夹具、底板与桌面固定方式；
- 同一传感器模块、同一测点和同一安装姿态；
- 同一供电配置（尤其是设定电压）；
- 实验过程可连续追溯，没有无法确认的重新安装、位移或长时间中断。

推荐格式是：`设备编号_夹具编号_电压_日期_本日第几轮`，例如 `fanA_rig01_9V_20260928_a`。使用英文、数字、下划线和短横线最易阅读；不要把类别名写进会话编号，例如不要写成 `fanA_normal_session`，因为同一会话本来就可能包含基线和故障段。

下列情况必须新建会话编号：

| 发生的变化 | 示例新会话 |
| --- | --- |
| 换了被测风扇 | `fanB_rig01_9V_20260928_a` |
| 改变设定电压 | 从 9 V 改为 6 V：`fanA_rig01_6V_20260928_a` |
| 更换夹具、重新夹紧底板或风扇发生位移后重新固定 | `fanA_rig02_9V_20260928_a` 或同夹具的新轮次 `fanA_rig01_9V_20260928_b` |
| 更换传感器模块、重新贴传感器、改变测点或方向 | 新建 `..._b`，并同步更新对应溯源字段 |
| 实验中断后无法确认硬件状态仍保持原样 | 保守起见新建 `..._b`，不要假定仍可比较 |

只是按计划把“全部紧固 → 加胶带/回退 M1 → 恢复紧固”切换，不需要新建会话，因为受控工况变化正是这轮实验要比较的对象。

#### 2. 本会话运行序号是什么

本会话运行序号（`run_index`）是同一个 `session_id` 内每个已保存 CSV 的**时间顺序编号**。从 `1` 开始，每保存一段就使用下一个整数；新建会话时再从 `1` 开始。它不是：

- 不是采集帧数（帧数填在“采集帧数”）；
- 不是故障等级（等级填在“故障等级”）；
- 不是胶带数量、松动圈数或重复次数；
- 不是整个项目的全局序号。

例如，在 `fanA_rig01_9V_20260928_a` 中按下面方式填写：

| `run_index` | 实际操作 | 客观工况 | 说明 |
| --- | --- | --- | --- |
| `1` | 全部紧固、无胶带 | `baseline` | 本轮起始基线。 |
| `2` | 在约定位置贴一片 `tape01` | `added_mass` | 与 `1` 比较不平衡变化。 |
| `3` | 取下胶带并恢复全部紧固 | `baseline` | 验证变化是否随工况恢复。 |
| `4` | M1 回退 1/4 圈 | `mount_looseness` | 与 `1`、`3` 比较松动影响。 |
| `5` | M1 恢复紧固 | `baseline` | 验证松动后的恢复情况。 |

若第 `4` 段通信完整、CSV 已保存，但现场发现风扇位移或标签不可信，仍应保留它的记录和编号（正式数据标为 `reject`，或作为 debug 证据）。不要删除后把下一次采集重新编号为 `4`；下一段应为 `5`，并在备注或 `quality_reason` 说明前一段被拒绝的原因。这样日志、CSV 和 manifest 的时间顺序始终可追溯。若串口错误导致程序根本没有生成 CSV，则没有产生采集记录；排除错误后可以仍使用未占用的 `4`，但应在现场日志中记下这次失败尝试。

#### 3. 最简单的填写规则

开始一轮新实验时先确定本轮的 `session_id`，此后每点击一次采集就把 `run_index` 加 1。只要设备、夹具、传感器/测点/姿态和供电配置任一改变，就停止递增旧会话，改用新的 `session_id` 并从 `run_index=1` 开始。窗口不会自动替你判断这些现实条件，因此这两个字段必须在实际操作时维护。

### 采集模式怎么选

| 模式 | 适用场景 | 保存位置与后果 |
| --- | --- | --- |
| `debug` | 串口、轴向、夹具、频谱或参数的试采；可以先采 5 帧。 | 写入 `04_数据集/debug_raw/`，不登记训练清单。 |
| `formal` | 现场工况和溯源都已确认、可作为训练候选的正式样本。 | 写入 `04_数据集/formal/`，自动在 `manifest.csv` 登记为 `pending`。 |
| `selftest` | 板端桩信号、帧协议、连续性或串口链路自检。 | 写入 `debug_raw/`，不进入训练。 |
| `calibration` | 六面静态标定、均值记录、传感器检查。 | 写入 `debug_raw/`，不进入训练。 |

旧版 `04_数据集/raw/` 仅保存历史文件，窗口不会向其中写入新数据。

## 3. 页面二：工况与标签

### 3.1 自动生成的模型标签

窗口只要求填写“客观工况”；模型标签由程序自动生成，不能手工覆盖，避免记录事实与训练标签冲突。

| 客观工况 | 自动模型标签 | 含义 | formal 是否允许 |
| --- | --- | --- |
| `baseline` | `normal` | 全部紧固、无胶带、无受控故障注入的正常基线。 | 允许 |
| `added_mass` | `unbalance` | 在已记录位置贴上胶带等受控附加质量造成的不平衡。 | 允许 |
| `mount_looseness` | `looseness` | 风扇与实验底座之间一个已编号安装紧固点的受控松动。 | 允许 |
| `unknown` | `unassigned` | 工况未知，或只做链路/初步观察。 | 仅 debug/selftest/calibration；formal 禁止 |

项目中的 `looseness` 不包括轴承故障、风扇在桌面上滑移或软性支撑晃动。轴承异常不在当前项目范围内。

### 3.2 共用标签

| 窗口标签 | 可填值 | 何时怎么填 |
| --- | --- | --- |
| 标签依据 | `controlled_injection` 或 `unknown`。 | 正常基线、已记录胶带、已量化松动填 `controlled_injection`；无法确认的调试/自检/标定填 `unknown`。formal 不能填 `unknown`。 |
| 标签可信度 | `confirmed`、`suspect`、`unknown`。 | 操作、现场状态和记录均可确认时填 `confirmed`；有疑点但仍要保存排查证据时填 `suspect`；未知工况填 `unknown`。formal 不能填 `unknown`，训练清单默认排除 `suspect`。 |
| 故障等级 | 非负整数，是受控试验的相对等级，不是绝对物理严重度。 | 基线填 `0`；一片/两片胶带可填 `1`/`2`；同一紧固点、同一方法下建议回退 1/4 圈填 `1`、1/2 圈填 `2`。 |

### 3.3 三类正式工况的填写样式

#### A. 正常基线：`baseline → normal`

用于“全部紧固、没有胶带”的对照段。

| 字段 | 示例 |
| --- | --- |
| 客观工况 | `baseline` |
| 标签依据 / 可信度 | `controlled_injection` / `confirmed` |
| 故障等级 | `0` |
| 胶带与松动字段 | 全部留空；胶带数量保持 `0` |
| 备注 | `正常基线；全部紧固；无胶带` |

基线不得混入胶带规格、胶带数量、松动紧固点、回退圈数或安装间隙。改变电压、夹具、测点、姿态或传感器模块后，不可继续沿用同一 `session_id`。

#### B. 受控不平衡：`added_mass → unbalance`

窗口会显示“贴胶带不平衡”分组。必须填写：

| 窗口标签 | 填写样式 |
| --- | --- |
| 故障等级 | `1`（一片）或 `2`（两片）；同一试验定义下连续递增。 |
| 胶带规格编号 | 可追溯的固定编号，例如 `tape01`。同一规格不要今天填 `tape01`、明天填“透明胶”。 |
| 胶带数量 | `1`、`2` 等正整数。 |
| 总质量 mg | 已称量时填写，例如 `120` 或 `240`；未知留空。 |
| 半径 mm | 从转轴到附加质量中心的距离，例如 `28`；未知留空。 |
| 角度 deg | 约定零度基准后的安装角度，例如 `0`、`180`；未知留空。 |
| 备注 | 例如 `tape01，一片，0°，未观察到位移`。 |

程序会使用 `fault_method=tape_mass`。正式数据至少需要故障等级 ≥ 1、胶带规格编号和胶带数量 ≥ 1。若胶带导致风扇位移，停止采集、重新固定；该段不能直接标记为 `pass`。

#### C. 安装固定处松动：`mount_looseness → looseness`

窗口会显示“安装松动”分组。先采一段全部紧固基线，然后只改变一个紧固点。建议先试 `M1` 回退 1/4 圈；确认没有位移、碰擦或自行旋出后，才尝试更大回退量。

| 窗口标签 | 填写样式 |
| --- | --- |
| 故障等级 | `1` 表示本试验定义的第一档，例如回退 1/4 圈；`2` 例如回退 1/2 圈。 |
| 松动方法 | `fastener_backoff` 表示回退螺栓；若使用定厚垫片制造间隙可填 `shim_gap`。 |
| 松动紧固点编号 | 例如 `M1`，必须与硬件标记一致。 |
| 回退圈数 | 例如 `0.25`、`0.5`；采用回退方式时必填。 |
| 安装间隙 mm | 采用定厚垫片时填写，例如 `0.50`；与回退圈数至少填写一项。 |
| 备注 | 例如 `M1 从基准紧固位置回退 1/4 圈；底板 C 形夹未改变`。 |

正式松动数据必须有故障等级 ≥ 1、松动方法、紧固点编号，以及正数的回退圈数或安装间隙。底板与桌面的夹紧状态不得变化。建议同一会话按“紧固基线 → 松动 → 恢复紧固基线”交替采集至少 3 轮；恢复后没有回到基线附近时，先排查夹具或测点变化。

### 3.4 非正式场景怎样填写

| 场景 | 推荐模式与填写方式 |
| --- | --- |
| 首次确认串口、X 轴和频谱 | `debug`；客观工况 `unknown`，标签依据/可信度均为 `unknown`，帧数先填 `5`，备注写明检查目的。 |
| 已贴胶带但只想先看频谱 | `debug`；仍可如实填写 `added_mass`、`controlled_injection`、`confirmed` 和胶带信息。它不会进入训练清单。 |
| 板端桩信号或连续性检查 | `selftest`；通常 `unknown` / `unknown` / `unknown`，设备编号可为 `board01`，备注写明桩信号或链路版本。 |
| 六面标定或静态均值 | `calibration`；通常 `unknown` / `unknown` / `unknown`，设备编号填写模块或开发板编号，备注写明静态姿态。 |
| 不确定是否发生位移、胶带是否脱落、松动量是否记错 | 保存为 `debug`，或 formal 先保持 `pending`/标为 `suspect`；不要把猜测补成 `confirmed`。 |

## 4. 页面三：溯源信息

下表字段在 `formal` 模式全部必填；调试、自检和标定也应尽量填写，便于复现。X 是固定的测量轴，Y 是静态安装时的重力参考轴；Y 不是运行中的“重力通道”。

| 窗口标签 | 含义与示例 |
| --- | --- |
| 夹具编号 | 刚性底板/夹具的稳定编号，例如 `rig01`。夹具改变时新建会话。 |
| 传感器模块编号 | MPU6050 模块的稳定编号，例如 `mpu01`。 |
| 传感器测点编号 | 模块固定在风扇的具体位置，例如 `fan_frame_top`。 |
| 安装姿态编号 | 能唯一解释 X 测量轴和 Y 重力参考轴的编号，例如 `x_measure_y_gravity`。 |
| Y 轴重力参考符号 | 静态基准安装时重力投影在 Y 上的符号：读数为正填 `+1`，为负填 `-1`。不要根据运行波形猜测。 |
| 标定记录编号 | 实际应用的标定记录。当前尚未接入补偿时填 `uncalibrated`；接入后填可追溯记录号。 |
| 实际烧录固件构建标识 | 实际烧入开发板的 Git 短提交号或构建标识，例如 `bb64fdf`，不能填写猜测值。 |
| 备注 | 不适合结构化字段但影响解释的事实，例如供电档位、测点复贴、异常噪声或已观察到的轻微位移。 |

## 5. 页面四：开始采集与结果判读

勾选“我已确认：硬件工况已设置、风扇稳定、串口未被其他程序占用”后，点击“提交并开始自动采集”。窗口会先按上述契约校验标签；校验失败时不会打开串口。接收进度和板端文本日志显示在该页。

采集完成后会自动打开结果窗口，包含：

- 技术完整性提示：收到的轴、丢帧、样本 ID 连续性，以及已收到的 CAP 板端累计统计；
- 平均谱 TOP-5：按 10～400 Hz、与板端一致的避让规则显示；
- 三联图：首窗前 100 ms 时域、全段平均幅值谱、逐窗主峰频率与交流 RMS；图同时保存到 `05_演示与输出/debug/`；
- 谐波族报告：辅助估计 1×、倍频和 RPM，并显示不确定性。

谐波推断不是独立转速证据。当前 TACH 不与振动帧同步接入；需要确认机械基频时，仍要使用同电压的独立 TACH 测量或跨电压谱线跟踪。

### 正式数据的质检结论

`formal` 采集写入 `manifest.csv` 后初始状态必为 `pending`。结果页的“正式数据质检”只会更新 manifest 中本次记录的可编辑字段，不会修改 CSV 的不可变采集事实。

| 质检结论 | 何时使用 |
| --- | --- |
| `pending` | 尚未完成现场复核，或暂时无法判断。此状态不会进入训练清单。 |
| `pass` | X 轴正确、丢帧和样本不连续均为 0；现场未位移；工况、标签、溯源和备注均与实际一致；恢复基线等必要复测无异常。 |
| `reject` | 丢帧、样本不连续、轴向错误、风扇位移、叶片擦碰、夹具改变、标签不确定或其他不应训练的情况。原因栏应写具体原因，例如 `M1 松动后整机位移`。 |

即使自动完整性检查通过，也不能自动标记 `pass`。`board_*` 统计若出现，是自开发板上电以来的累计值；没有收到 CAP 行时需按提示复位并延长调试采集检查。

## 6. 训练前

仅 schema v4、`data_role=formal`、`quality_status=pass`、文件 SHA-256 与 manifest 一致、且标签不为 `suspect` 的记录会被默认选入训练。完成至少两台设备的正式采集和质检后，运行：

```powershell
& .\.conda\python.exe .\03_Python工具\make_dataset.py --test-device fanB
```

把 `fanB` 换成实际留作测试集的设备编号。输出位于 `04_数据集/processed/`。

## 7. 常见问题

### 窗口无法打开或提示 Tcl/Tk

请从项目根目录使用本手册的命令启动，不要使用系统 Python。统一脚本会自动定位项目 `.conda` 中的 Tcl/Tk 运行时；若仍失败，记录完整终端错误并检查 `.conda` 环境是否完整。

### 串口打开失败

确认端口号、USB 连接和波特率；关闭串口助手；不要同时运行两个采集窗口或 `recv.py`。

### 正式采集提示标签校验失败

逐项核对：formal 不能选 `unknown` 工况；必须填写标签依据/可信度和全部溯源字段；不平衡必须有胶带规格与数量；松动必须有紧固点和正数回退圈数或间隙；真实设备必须填写设定电压。

### 收到的不是 X 轴

停止使用该段数据，检查固件发送轴和传感器安装方向。不要通过改文件名或编辑 CSV 把 Y/Z 轴数据伪装成 X 轴。
