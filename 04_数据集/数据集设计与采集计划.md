# 数据集设计与采集计划


## 1. 当前数据状态

正式数据使用 schema v3：baseline→normal、added_mass→unbalance、mount_looseness→looseness；X 为测量轴、Y 为重力轴，松动需量化紧固点和回退圈数或间隙。manifest.csv 仅有表头且 formal/ 仅有占位文件，正式样本为 0。本页采集矩阵是待执行计划；实际流程以[采集操作手册](采集操作手册.md)和[数据集契约](README.md)为准，风扇 B 完全留出测试。


## 2. 数据集设计

> 深度学习不是"写代码"，是"造数据"。这个项目能不能在简历上站住，**70% 取决于数据集的规范程度**。

### 2.1 采集与标注

- 固件提供一个"**采集模式**"：上行连续上送**原始加速度样本**（int16，带帧序号），不在此模式做推理；当前工程的固件帧协议保持不变，标签由 PC 采集时写入文件头。
- PC 端 `03_Python工具/recv.py` 在打开串口前校验结构化标签，接收后把元数据写成 `# meta_json=...`，并按 `data_role` 写入 `04_数据集/formal/` 或本地 `04_数据集/debug_raw/`。正式数据另追加到 `04_数据集/manifest.csv`。
- 采集表单以“客观工况 + 证据 + 采集条件”为核心：设备、会话、时间、工况、标签依据/可信度、故障等级、胶带信息、松动紧固点与回退圈数/间隙、电压、轴向、采样参数、质量状态、备注。**不包含夹具版本、传感器编号、传感器安装点**。
- 文件名只携带可检索事实（记录号、设备、工况、电压、轴和序号范围），不把 `target_label` 复制进文件名，避免文件名和标签清单不一致。

### 2.2 采集矩阵

**对象分级（关键决策，已定）**：

- **风扇 A＝训练与验证数据源**：完成正常、不平衡、机械松动的全部受控组合；训练/验证切分必须按完整采集段或会话分组。
- **风扇 B＝留出测试设备**：同样完成三类受控组合，但全部记录不进入训练，用于评估跨设备泛化。
- 只有两台设备时，严格留出 B 意味着训练设备只有一台，评估方差会较大。报告结果时必须说明这一限制，不能把切窗数量当作设备多样性。

| 维度  | 取值                                                       | 说明                                               |
| --- | -------------------------------------------------------- | ------------------------------------------------ |
| 设备  | 12 V 直流风扇 A、B 共 2 台                                      | B 完全留出；A 用于训练/验证                                |
| 状态  | 正常 / 不平衡（胶带 1–2 档）/安装固定处机械松动（建议 M1 回退 1/4、1/2 圈）         | 每类每设备先做 ≥ 5–10 段，每段 10–30 s；松动需做恢复基线复测       |
| 转速  | 2–3 档电压；无测速设备时用变电压谱线跟踪确定机械基频                         | 每个状态覆盖相同电压档，避免模型只学电压                         |
| 位置  | 同一固定方式与测点保持不变                                             | 不把夹具版本、传感器编号、安装点作为表单字段；若发生临时变化写入 notes |
| 时间  | 不同天多次采集                                                  | 引入真实差异                                           |

**固定建议**：利用风扇框架原安装孔，以 M4 螺栓、平垫圈和防松螺母连接到刚性木板/厚亚克力板，再用两个 C 形夹把底板夹紧桌面；传感器固定在风扇框架上。给安装紧固点编号 M1、M2……，正常与不平衡时全部紧固，松动时只回退指定点。不得用橡皮筋、软泡棉或可移动压重物作为正式夹具，因为它们会改变支撑刚度或允许整机滑移。

> 数据量级参考：两台风扇的原始数据几十 MB 即可，切窗后可形成大量窗口；但窗口数不能替代设备数。三类应在设备、电压和采集段维度尽量均衡。

### 2.3 数据划分与增强

- 先在 `manifest.csv` 中人工复核 `quality_status`：只有 `pass` 才能进入训练；`pending` 与 `reject` 只保留作审计或排错。
- `03_Python工具/make_dataset.py` 默认排除 `label_confidence=suspect`，按 `device_id` 留出测试设备，避免同一台风扇的相邻窗口泄漏到训练和测试；设备不足两台时脚本会明确提示，不能把随机切窗结果冒充泛化测试。
- 离线增强：滑窗重叠、轻微加噪、幅值缩放、切段拼接——增强信号多样性；增强结果只能继承原始记录的来源和标签，不能重新随机命名。
- 正式原始数据可按里程碑提交 GitHub/LFS；调试数据、串口日志和中间处理结果留在本地 `debug_raw/`、`06_笔记与踩坑/raw_logs/`、`04_数据集/processed/`。

### 2.4 可视化与检查

- 阶段 1：串口波形实时显示（matplotlib 动画或现成 SerialPlot）——证明采集链路通；
- 阶段 2：频谱显示（同一工具切到 FFT）——证明 FFT 正确（能看到 1× 峰随贴片变大）；
- 阶段 3：训练后做 confusion matrix + 频谱样例图，放 GitHub README 与简历附件。
