# Q-06：1024 点窗口采样时序与漏采验证

## 验证日期与版本

- 日期：2026-09-26。
- 测试分支：`timing-test`。
- 固件打点提交：`4957096 test: instrument 1024-point sampling`。
- 测试证据提交：`75ce768 test: add sampling timing debug evidence`。
- 主线未合并临时计时打点代码；本记录保留验证结论和证据位置。

## 测试条件

- 采样率：1000 Hz。
- 窗口长度：1024 点。
- 数据源：真实 MPU6050。
- 测量轴：X。
- 串口：460800 baud，`COM13`。
- 接收命令：`recv.py --data-role debug --frames 6`。
- 采集结果：6 帧、6144 个样本、串口丢帧 0。

## 测试结果

| 窗口 seq | span_ticks | miss_ticks | boundary_gap | read_fail |
|---:|---:|---:|---:|---:|
| 1 | 1023 | 0 | 0 | 0 |
| 2 | 1023 | 0 | 51 | 0 |
| 3 | 1023 | 0 | 52 | 0 |
| 4 | 1023 | 0 | 51 | 0 |
| 5 | 1023 | 0 | 51 | 0 |

`span_ticks=1023` 表示第 1 点到第 1024 点之间正好有 1023 个 1 ms 节拍；`miss_ticks=0` 表示窗口内部没有漏采节拍。`boundary_gap=51～52` 表示窗口之间存在约 51～52 ms 的暂停，来自 FFT、阻塞式串口原始帧发送和调试文本日志。

## 结论

1. 1024 点窗口内部的采样连续性验证通过：每个已完整记录的窗口均为 `span=1023`、`miss=0`、`readfail=0`。
2. 串口帧接收验证通过：`seq=1..6` 连续，`lost_frames=0`。
3. 跨窗口连续 1 kHz 采样尚未通过：当前主循环在处理和发送期间暂停采样，窗口边界仍有约 51～52 ms 间隔。
4. 本次数据属于 debug 时序证据，不进入 `manifest.csv`，也不作为正式训练样本。

原始 CSV 和板极日志保存在远程 `timing-test` 分支，不复制到主线：

## 后续动作

- 若项目只要求每个 FFT 窗口内部等间隔，当前结果可作为通过证据。
- 若项目要求跨窗口连续采样，应取消“采样—处理—发送”串行暂停结构，改为采样与处理/串口发送解耦后重新测试。

## 2026-09-26 源码改造（尚未上板验收）

- 当前工作树已改为 MPU6050 加速度 FIFO 批量读取、三槽窗口队列和 USART1 TX DMA 队列；主循环不再调用采样暂停接口。
- 加速度帧新增 `first_sample_id`（32 位、小端）。`recv.py` 将检查后一帧的该值是否等于前一帧首编号加样本数；正式采集遇到帧缺失或样本不连续将拒绝写入。
- 本页上方的 `boundary_gap=51～52` 只适用于改造前的 `timing-test` 固件，不得用于证明本版本的连续性。完成重新编译、烧录和至少 600 窗连续实测后，才可更新本页结论。

## 2026-09-26 连续采样版本目标板验收

### 条件与证据

- 已重新编译、烧录连续采样版本；数据源为真实 MPU6050，采样率 1000 Hz，窗口 1024 点，测量轴 X，串口为 COM13 / 460800 baud。
- 接收命令为 `recv.py --data-role debug --frames 600`，本次只作传输与连续性验收，不作为正式训练样本。
- 原始 CSV：[20260926T193800_0800_fanA_r001_fanA_unknown_9V_X_r0001-0600.csv](../../04_数据集/debug_raw/20260926T193800_0800_fanA_r001_fanA_unknown_9V_X_r0001-0600.csv)，板端日志：[20260926_193800_boardlog.txt](../../05_演示与输出/boardlog/20260926_193800_boardlog.txt)。

### 结果

| 项目 | 实测结果 | 判定 |
|---|---:|---|
| 接收帧 / 样本数 | 600 帧 / 614400 样本 | 通过 |
| `seq` | 1～600 连续 | 通过 |
| `first_sample_id` | 每帧递增 1024，`sample_id_gaps=0` | 通过 |
| PC 端帧丢失 | `lost_frames=0` | 通过 |
| FIFO / IIC / 窗口 / TX 错误 | `fifo_ovf=0`、`iic_fail=0`、`win_drop=0`、`tx_drop=0`、`tx_err=0` | 通过 |
| 连续性中断 | `break=0` | 通过 |

板端整段日志中的统计均为零，最终统计中的 FIFO 批量读取量为 `batch=2`；这表示当前调度下每次正常从 FIFO 取到 2 个加速度样本，并非异常或丢样。

### 更新结论

连续采样版本已通过目标板长时传输与跨窗口连续性验收。旧版 `boundary_gap=51～52 ms` 的结论仅适用于改造前的阻塞式采样—处理—发送结构，已不适用于此版本。
