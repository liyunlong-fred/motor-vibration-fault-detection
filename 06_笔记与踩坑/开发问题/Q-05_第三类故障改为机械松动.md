# 第三类故障改为机械松动


## 1. 当前结论

决策已落实到 schema v3、config.json、元数据校验和采集手册，但无正式样本。下一步验证 M1 回退 1/4、1/2 圈与恢复紧固的往返重复性；位移、碰擦或不回基线的样本必须拒绝。


## 2. 问题概述

第三类故障由轴承磨损改为安装固定处机械松动

### 2.1 编号 / 标题

Q-05 — 在只有两台 12 V 风扇、MPU6050 和基础手工条件下，第三类故障如何做到标签可信且可重复？

### 2.2 时间 / 阶段

2026-09-24；D5 正式采数前的方案修订。

### 2.3 现象 / 决策触发

原方案依赖“异响 → 疑似轴承磨损”的间接标签；不拆机无法确认根因，人工损伤轴承也难控制损伤位置、程度与安全性。用户决定把第三类改为检测安装固定处问题的机械松动，并明确不保留轴承异常扩展项。

### 2.4 分析过程

比较后认为安装松动更符合现有条件：可在风扇原安装孔处注入、无需破坏电机、可以恢复基线，并能用紧固点编号和回退圈数/间隙量化。主要混杂因素是底板滑移、软连接、传感器位置变化及紧固件自行旋出，因此夹具边界必须固定。

### 2.5 根本原因

旧第三类的故障真值不可直接验证，训练标签存在把异响或设备个体差异误当轴承磨损的风险；受控安装松动则能把故障定义收窄到可操作、可恢复、可记录的固定点异常。

### 2.6 解决方法

三类改为 `normal / unbalance / looseness`，客观工况改为 `baseline / added_mass / mount_looseness`，数据契约升级为 schema v3。刚性底板用 C 形夹固定桌面，正常/不平衡时全部安装点紧固；松动时只改变指定点（如 M1 回退 1/4 圈或 1/2 圈，或加入定厚间隙），记录 `loose_fastener_id`、`loosen_turns` / `mount_gap_mm`。轴承异常不进入规划、训练或扩展清单。

### 2.7 验证结果

方案、标签契约、采集校验和操作手册已完成同步；真实可分性尚未验证。正式采集前必须完成至少 3 轮“紧固基线 → 松动 → 恢复紧固基线”，确认松动特征重复出现且恢复后回到基线附近。

### 2.8 经验与可复用点

故障分类先保证“真值可知、注入可控、状态可恢复”，再讨论模型精度。若整机位移、叶片碰擦、底板松动或恢复后不回基线，该段不能算合格的安装松动样本。Q-01 中关于轴承类别的历史分析仅代表当时方案；其“主特征采用加速度谱”的结论仍可用，但类别和实验裁决指标由本条取代。
