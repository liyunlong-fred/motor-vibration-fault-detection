# 开发问题与解决记录


## 1. 维护规则

每个问题在独立 Q 文件持续补充，不再回填历史总稿。记录必须包含日期、环境、复现、证据和结论；新问题从 Q-06 递增。Q-01 的轴承磨损仅是历史背景，当前分类范围以 Q-05 为准。


## 2. 记录说明

> **用途**：沉淀真实问题及其解决过程，作为调试手册、面试复盘素材和项目证据。
> **与风险文档的分工**：[风险、扩展与参考资料](../../01_文档/项目规划/09_风险扩展与参考资料.md)记录事前预防；本目录记录已经发生的问题、排查过程、根因和验证结果。
> **与其他记录的分工**：本节只放**整理后的结论**（文字可检索、可引用、可写进文档）；原始截图、示波器图和临时调试代码放项目目录 `06_笔记与踩坑/`，板端串口日志放 `05_演示与输出/boardlog/`；两边用**问题编号**（Q-01、Q-02…）互相引用。

### 2.1 登记规则

1. 你提出开发中遇到的具体问题（现象/报错/截图） → 助手解答，可能来回多轮；
2. 你说"**记录这个问题和回答**" → 助手把**同一个问题的多轮对话合并整理成一条**：去掉来回试探与重复内容，保留结论、关键命令/代码、报错原文；
3. 在“问题索引”追加一行，并新建或更新对应的 Q-xx 独立文档；
4. 更新该问题的当前结论、验证证据和可复用经验；不维护历史总稿的修订记录；
5. **编号只增不改**：后续补充同一问题用"Q-01（补充）"或直接改写该条正文，**不新开编号**，这样你在笔记/简历里可以稳定引用。

### 2.2 记录模板

| #   | 字段      | 写什么                                           |
| --- | ------- | --------------------------------------------- |
| 1   | 编号 / 标题 | 形如 `Q-01 Keil 下载报 L6047U`——"编号 + 一句话现象"       |
| 2   | 时间 / 阶段 | 日期 + 对应里程碑（D0…D14），方便回溯当时做到哪一步                |
| 3   | 现象      | **报错原文**或实测现象，关键行照抄不要转述（以后才能搜到）               |
| 4   | 排查过程    | 做了哪些验证、排除了哪些可能——**这段最有面试价值**，体现的是定位思路而不是"背答案" |
| 5   | 根本原因    | 一句话讲清"为什么会这样"（机制层面，不是"重新装一遍就好了"）              |
| 6   | 解决方法    | 可复现的具体步骤（菜单路径 / 命令 / 代码片段 / 接线改动）             |
| 7   | 验证结果    | 改完怎么确认真的好了（现象消失、指标数字、连续运行多久没复发、留了哪张图）         |
| 8   | 经验与可复用点 | 同类问题的快速判断口诀；能不能写进简历、面试被问到时怎么讲                 |
