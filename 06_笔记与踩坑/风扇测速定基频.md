# 风扇测速与机械基频确认

> [!note] 目标
> 优先用独立 TACH 测速确认机械 1×；当前没有测速设备，因此项目先采用变电压谱线跟踪估计基频。两种方法都保留在本文，尚未记录最终实测结果。

## 零、当前采用：无测速设备时的变电压谱线跟踪

该方法能给出“最可能的机械 1×”，但不能像 TACH 一样独立证明绝对转速。报告中应写“估计基频”，不要写“实测 RPM”。

1. 保持风扇、底板、传感器和紧固状态不变，正常工况下分别采 6 V、9 V、12 V；每档稳定 20～30 秒后采至少 20 帧。
2. 对每档运行 `harmonics.py`，并填写对应电压限制候选范围：

```powershell
python -B 03_Python工具\harmonics.py <实际CSV路径> --supply 6 --plot
python -B 03_Python工具\harmonics.py <实际CSV路径> --supply 9 --plot
python -B 03_Python工具\harmonics.py <实际CSV路径> --supply 12 --plot
```

3. 把三个电压下同步向高频移动的一组谱线连成“阶次族”。候选 f0 应满足：2×、3×等峰与它近似成整数倍，并且随电压变化保持这一倍频关系。
4. 若 2× 比 1× 强，不要直接把最强峰当 f0；比较 `f` 与 `f/2` 两组候选能否解释更多整数倍谱线。当前工具会结合电压与额定转速范围辅助这一判断。
5. 在正常、不平衡、机械松动三类中使用同一个 f0 估计规则。标签来自受控工况，不来自“哪根峰看起来像故障”。

验收条件：三档电压都能找到连续移动、倍频关系一致的候选族；同一电压重复采集时 f0 误差不超过一个 FFT bin（约 0.98 Hz）或给出合理的转速波动解释。若候选族不唯一，就先把 f0 标为未确认，不据此下物理结论。

我有逻辑分析仪能代替stm32直接测量转速吗？

可以。对于当前“确认36 Hz还是73 Hz为机械1×”这个一次性任务，逻辑分析仪比先写STM32输入捕获更快、更直接。

## 一、接线

前提：已经确认风扇确实有独立TACH线。

全部断电后连接：

```text
风扇电源 +12V ───────── 风扇 +12V

风扇电源 GND ───┬───── 风扇 GND
               └───── 逻辑分析仪 GND

3.3V ── 4.7kΩ ──┐
                ├───── 风扇 TACH
                └─1kΩ─ 逻辑分析仪 CH0

风扇 PWM ───────── 保持原接法
```

注意：

- 风扇继续由独立电源供电。
- 逻辑分析仪必须和风扇共地。
- TACH上拉到3.3 V，不要上拉到12 V。
- 不要把风扇12 V电源线接入逻辑分析仪。
- 逻辑分析仪是否允许3.3 V输入，需要看型号规格；绝大多数可以，但不能假定它耐受12 V。
- 逻辑分析仪如果提供“3.3 V输出”，也要确认该针脚确实是电源输出且允许外接上拉。最稳妥的是使用开发板的3.3 V或独立3.3 V电源，只给4.7 kΩ上拉使用。
- 建议CH0前串1 kΩ保护电阻。

如果未上拉时测得TACH对地明显高于3.6 V，先不要连接分析仪，需要检查是否认错针脚或风扇存在内部高压上拉。

## 二、逻辑分析仪设置

推荐参数：

```text
通道：CH0
采样率：1 MHz
采样时间：5～10秒
触发：下降沿
数字阈值：3.3 V/CMOS模式（如果软件可选）
```

测速信号一般只有几十到一百多Hz，实际上100 kHz采样率已经足够；设置1 MHz便于观察毛刺和边沿质量。

启动顺序：

1. 风扇和分析仪都断电。
2. 完成接线。
3. 启动逻辑分析仪软件。
4. 开始采集。
5. 再打开风扇电源。
6. 风扇稳定20～30秒后，再采一段5～10秒的稳定波形。

## 三、怎样从波形计算RPM

测量两个相邻同类型边沿之间的时间：

```text
下降沿 → 下一个下降沿
```

记周期为`T`秒：

```text
TACH频率 = 1 / T
RPM = TACH频率 × 60 / 每转脉冲数
```

标准四线PWM风扇通常每转2脉冲，因此：

```text
RPM = TACH频率 × 30
RPM = 30 / T
```

如果软件直接显示频率：

| TACH频率 | 按2脉冲/转计算 | 机械转频 |
|---:|---:|---:|
| 60 Hz | 1800 rpm | 30 Hz |
| 73 Hz | 2190 rpm | 36.5 Hz |
| 80 Hz | 2400 rpm | 40 Hz |
| 100 Hz | 3000 rpm | 50 Hz |
| 116.7 Hz | 3500 rpm | 58.3 Hz |

例如测得：

```text
相邻下降沿间隔 T = 13.66 ms
TACH频率 = 1 / 0.01366 = 73.21 Hz
RPM = 73.21 × 30 = 2196 rpm
机械1× = 2196 / 60 = 36.60 Hz
```

那么可以确认：

```text
36.6 Hz = 机械1×
73.2 Hz = 机械2×，同时也接近TACH脉冲频率
```

这正好能解释现有频谱中73 Hz比36 Hz强的现象。

## 四、推荐的实际测量流程

分别测：

```text
6 V、9 V、12 V
```

每档执行：

1. 风扇固定方式不变。
2. 不贴胶带，先测正常状态。
3. 调整电压。
4. 等待20～30秒稳定。
5. 采集5～10秒TACH波形。
6. 在稳定区任选10个以上完整周期。
7. 使用软件计算平均频率，或者计算：

```text
平均周期 = 选中时间长度 / 完整周期数
```

8. 记录：

| 电压 | 周期数 | 总时间 | 平均周期 | TACH频率 | RPM | 机械1× |
|---|---:|---:|---:|---:|---:|---:|
| 6 V |  |  |  |  |  |  |
| 9 V |  |  |  |  |  |  |
| 12 V |  |  |  |  |  |  |

9. 再贴胶带重复测量，确认胶带是否导致转速变化。

不要只量一个周期，因为电机换相、控制器调速和边沿抖动会带来小误差。测10～50个周期取平均更可靠。

## 五、波形应该是什么样

正常情况：

```text
3.3V ─────┐     ┌────────┐     ┌────────
           │     │        │     │
0V         └─────┘        └─────┘
            <---  T  --->
```

判断：

- 周期基本均匀：正常。
- 偶尔出现非常窄的脉冲：可能有干扰，计算时应排除。
- 电平始终为高：没有TACH脉冲、没有共地或针脚错误。
- 电平始终为低：接错线、TACH被短路或转子恰好停在拉低状态。
- 周期忽长忽短：接触不良、风扇调速不稳定或分析仪阈值不合适。
- 一个正常周期中出现多个细小跳变：增加数字去毛刺，检查地线和线长；必要时在TACH节点增加约1 nF到地的小电容。

## 六、一个重要限制

逻辑分析仪只能测到“每秒多少个TACH脉冲”。要换算真实RPM，仍需知道每转脉冲数PPR。

如果这是符合标准的四线PWM风扇，可按2脉冲/转计算。如果只是使用四孔插头的非标准风扇，则应查型号资料；否则逻辑分析仪本身不能证明它是每转1、2还是4脉冲。

## 七、是否还需要STM32测速

当前阶段可以完全不用STM32测速：

```text
逻辑分析仪测速 → 得到真实机械1× → 与FFT对拍
```

确认基频后，如果最终产品界面需要实时显示RPM，或者希望每份CSV自动记录转速，再把同一根TACH线接入STM32的PA5/TIM2_CH1即可。

当前先完成“6 V、9 V、12 V 正常基线 + 变电压谱线跟踪”。以后若获得逻辑分析仪或示波器，再按本文 TACH 流程补做独立验证，并把“估计 f0”升级为“实测机械 1×”。
