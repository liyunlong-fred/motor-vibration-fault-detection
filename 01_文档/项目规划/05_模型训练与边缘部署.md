# 模型训练与边缘部署


## 1. 当前实现边界

训练、量化、X-CUBE-AI 导入和板上推理均尚未开始。模型结构、资源预算与部署步骤均为后续设计；必须先完成正式采集、质检与设备留出训练清单。


## 2. 离线训练

### 2.1 可选路线

| 路线             | 输入                      | 模型                                                     | 优点                  | 缺点                | 部署                                 |
| -------------- | ----------------------- | ------------------------------------------------------ | ------------------- | ----------------- | ---------------------------------- |
| A. 特征 + 浅模型    | 相关页面 的 10–16 维特征        | 逻辑回归 → MLP(16-16-3)                                    | 简单、可解释、数据需求小、开发快    | 特征工程决定上限          | X-CUBE-AI 秒级转换                     |
| B. 频谱 + 1D-CNN | 对数幅度谱（0–400 Hz，256 bin） | Conv1D(8,3)-ReLU-MaxPool-Conv1D(16,3)-GAP-FC(3)，参数量几 K | 端到端学习特征、上限高、简历更"AI" | 数据/调参成本高、量化注意算子支持 | X-CUBE-AI（校验 Conv1D 支持；不行就 MLP 保底） |

### 2.2 训练工作流

```text
tools/
├─ collect.py        # 串口采集打标（相关页面）
├─ make_dataset.py   # 原始数据 → 切窗 → (特征 或 频谱) + 标签 → .npz
├─ train_feature.py  # 路线 A：特征 + MLP
├─ train_cnn.py      # 路线 B：频谱 + 1D-CNN（PyTorch/TF）
├─ quantize.py       # int8 量化（PTQ，用校准集）
├─ export_ai.py      # 导出为 X-CUBE-AI 可导入的 ONNX/TFLite
└─ eval_offline.py   # holdout 测试：准确率、混淆矩阵、每类 precision/recall
```

- 评价指标看 **confusion matrix + 每类召回率**，别只看总准确率（类别不平衡会骗人）；
- 先 float32 跑通全流程 → 再 int8 量化，量化后指标下降 <2–3% 可接受；
- 保存：模型文件、量化校准集、训练日志、复现 seed。

### 2.3 结果表述原则

- "数据集为实验室自建：2 台 12 V 直流风扇，受控采集正常、不平衡、安装固定处机械松动，共约 X 万窗；其中风扇 B 完全留出做跨设备测试，测试准确率 Y%，int8 量化后 Z%（均填写真实值）"；
- 主动说明局限："真实产线故障谱更复杂，本作品验证了方法链路与端侧可行性；工业落地需按目标设备重新采集/迁移校准（预留了自学习阈值方向）。"——比吹"解决产线痛点"更可信；
- 局限口径："机械松动是安装固定处的受控故障，不等同于轴承或所有工业松动；当前只有两台设备，泛化结论仍需更多设备验证。"

## 3. 部署与在线推理

### 3.1 部署路线

|      | X-CUBE-AI（ST 官方）                                 | TensorFlow Lite Micro |
| ---- | ------------------------------------------------ | --------------------- |
| 集成   | CubeMX 一键加入，生成 C 网络                              | 手动移植解释器源码             |
| 支持   | 各主流框架模型转 ONNX/TFLite 后导入；提供**闪存/RAM/周期数预估**与板上验证 | 通用 TFLite 模型          |
| 量化   | 支持 int8 PTQ                                      | 支持 int8               |
| 上手难度 | 低（**强烈推荐新手**，与 CubeMX+Keil 流程无缝）                 | 中                     |
| 封闭性  | 生成代码可读性一般、绑定 ST                                  | 开源可移植                 |

### 3.2 部署步骤

1. PC 导出模型（ONNX）→ CubeMX 中启用 X-CUBE-AI 插件 → 导入 → 选 **int8 量化 + 校准集** → 生成 `network.c/h`；
2. 查看工具输出的 ROM/RAM/周期数预估，对照 相关页面 预算；
3. Keil 工程中加入生成代码，封装 `model_infer.c`：输入特征/频谱 → 输出 3 类概率；
4. 集成进决策状态机（相关页面）；
5. **板上实测**：推理耗时（GPIO 包络/DWT 计数）、RAM/Flash（map 文件），回填 相关页面 表；
6. 数值一致性自检：同一段数据，PC 端 float 结果 vs 板上 int8 结果，概率分布应接近（量化误差可视化）。

### 3.3 资源预算

| 项                      | 估算                                 | 说明                 |
| ---------------------- | ---------------------------------- | ------------------ |
| FFT 缓冲（1024 点 float32） | ~4 KB + 窗函数/源缓冲 ~4 KB              |                    |
| 特征/激活/网络               | 数 KB–几十 KB                         | 以 X-CUBE-AI 报告为准   |
| 屏幕相关缓冲（官方 LCD 例程自带）    | 以官方例程 map 文件为准                     | 与算法内存分开统计，不挤占本项目预算 |
| 合计                     | 算法侧预计 < 32 KB RAM / < 100 KB Flash | 用 map 文件核实后回填      |

## 4. 后续扩展

- 架构升级：FreeRTOS 任务化（采样/推理/UI 分离），简历加"多任务实时调度"；
- 感知升级：换宽带宽加速度计（IIS3DWB/模拟输出传感器 + ADC），研究更高转速下的安装松动与结构响应；
- 交互升级：蓝牙/WiFi 上报、手机小程序/上位机仪表盘；
- 算法升级：阶次分析（order tracking）抗转速变化、自动阈值自校准/少样本迁移到新设备；
- 工程化：看门狗、低功耗（间歇巡检模式）、批量标定、产线小规模试用（如能接触到真实设备是巨大加分）。
