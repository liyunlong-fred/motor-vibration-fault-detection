# 简历答辩与学习路线


## 1. 当前使用边界

简历只能引用已有采样、FFT、串口链路和历史对拍证据。模型精度、推理耗时、报警延迟、屏幕展示和正式数据统计均未产生当前可引用证据。分类名称统一为安装固定处机械松动。


## 2. 简历与答辩

### 2.1 简历模板

> **低成本边缘端电机振动故障检测系统（STM32 + TinyML）**｜独立开发
> 
> - 面向小型电机/风扇离线巡检场景，设计"采集→FFT→特征→推理→报警"闭环：以 1 kHz 采样 MPU6050 加速度信号，CMSIS-DSP 实现 1024 点加窗 FFT 频谱分析；
> - 自建打标数据集（2 台 12 V 直流风扇、3 类〔正常/不平衡/安装固定处机械松动〕，约【X】万窗；1 台设备完全留出验证），离线测试准确率【Y】%，int8 量化后【Z】%；
> - 部署轻量级神经网络至 **正点原子探索者 STM32F407（Cortex-M4F @168 MHz）** 本地离线推理（X-CUBE-AI，模型 ROM【A】KB / RAM【B】KB），单帧处理耗时【C】ms（实测），端到端报警延迟 ≤【D】s（实测）；连续运行 10 min 零误报【实测条件】；
> - 4.3″ 彩色触摸屏实时显示状态/置信度/实时频谱，蜂鸣器 + 继电器联动报警（多窗投票 + 滞回防抖）；整机成本约【E】元（含屏开发板约 ¥250）。

### 2.2 诚信原则

- 凡是"延迟/准确率/误报"数字**必须来自你的实测或离线评估**，且能当场复现；

- 描述用词准确：数据是**自建受控故障样本**，机械松动仅指安装固定处；系统定位是**方法验证/演示级**，不要写成"已量产部署在产线"；

- 面试被追问数据来源时，直接讲采集矩阵与局限（相关页面 口径），反而建立信任。

### 2.3 高频问题与答复要点

| 可能的问题               | 应答要点                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------- |
| 为什么用频域不用时域？         | 特征物理意义明确、抗安装差异、对小型模型更友好（相关页面）                                                               |
| 为什么不在云端/上位机做 AI？    | 离线场景：数据不出厂、无网络延迟与成本、隐私合规、断网可用                                                               |
| 采样率为何 1 kHz？带宽够吗？   | 对象是低转速风扇；Nyquist+DLPF 约束；承认局限并给出宽带宽传感器升级路径（相关页面）                                            |
| 为什么选 F407 而不是 F103？ | F103（M3）无 FPU/DSP，推理偏慢；F407（M4F 168 MHz）跑量化模型余量大，X-CUBE-AI 官方支持；选正点原子板是因为教程/Keil 生态一致，开发效率高 |
| 模型多大？为什么量化？         | 用 X-CUBE-AI 报告与实测 RAM/ROM 回答；int8 减小 4× 并提速，量化损失可控                                          |
| 转速漂移怎么办？            | 特征相对化 + 自动基频估计；进阶用阶次分析（order tracking）                                                      |
| 换一台没见过的设备还能准吗？      | 明确讲：风扇 B 完全留出的测试结果；同时承认只有两台设备，仍需更多设备验证                                          |
| 误报怎么处理？             | 多窗投票、概率 EMA、滞回阈值、置信度下限                                                                      |
| 机械松动标签凭什么可信？          | 指定紧固点按圈数/间隙受控注入，并做“松动→恢复紧固→回到基线”的往返重复验证                                                        |
| FFT 里加窗是为什么？        | 泄漏与旁瓣、Hann 窗、幅度修正概念（背熟）                                                                     |
| 你踩过最大的坑？            | 从 D3–D10 的日志里挑一个真实问题（如采样丢点/假 FFT/训练与部署特征不一致），按"现象→排查→解决→沉淀"讲                                |

## 3. 学习路线

结合你现有的基础（F103 HAL 实验：串口、按键中断、点灯），建议按"用到再学、学过即用"补：

| 主题                 | 本项目用到                    | 学习入口建议                                     |
| ------------------ | ------------------------ | ------------------------------------------ |
| I2C 总线             | MPU6050 读写（4.3″ 屏不走 I2C） | 你的知识库笔记 + 正点原子《探索者开发指南》I2C 章节；逻辑分析仪抓波形理解时序 |
| 中断与 NVIC           | FIFO 水印中断、按键 EXTI        | 已做过按键中断实验，直接复用概念                           |
| DMA                | I2C/UART 搬运、双缓冲          | 结合 HAL 例程学"外设→内存"不占 CPU                    |
| 定时器                | 采样节拍/看门狗心跳               | 已具备基础                                      |
| 显示屏驱动              | 点亮 4.3″ 屏、画大字/频谱（照官方例程）  | 《探索者开发指南》LCD 显示实验章节                        |
| 信号与系统基础            | 采样定理、DFT/FFT、泄漏与窗        | B 站《傅里叶变换》可视化视频 + scipy 动手算                |
| CMSIS-DSP          | arm_rfft_fast_f32 等      | ARM 官方文档 + 例程（相关页面）                         |
| Python/numpy/scipy | 采集、FFT 对照、画图（见下）         | 见下方"Python 最小学习路线"                         |
| 机器学习基础             | 数据划分、混淆矩阵、过拟合            | 吴恩达 ML 课或西瓜书前几章，够用即可                       |
| TinyML/模型部署        | 量化、X-CUBE-AI             | X-CUBE-AI 官方文档/视频；《TinyML》一书可选             |
| Git/GitHub         | 代码与数据集管理                 | 用起来即学，遇到再查                                 |

> 提醒：**不要先系统性学完再动手**。以 D1–D14 里程碑为驱动，缺什么补什么，2 周内就能滚出完整项目；系统性补课放到项目之后。

### 3.1 Python 最小学习路线

先用一张表讲清楚"哪些环节**必须写 Python**、写多少"：

| 环节（对应天数）          | 用 Python 做什么                 | 难度/时长    | 能否绕开                                    |
| ----------------- | ---------------------------- | -------- | --------------------------------------- |
| 数据采集（D3–D6）       | 用 pyserial 收串口原始数据、按标签存文件    | ★☆ 半天    | 可先用串口助手手动存盘，但批量打标/管理仍要脚本                |
| 可视化（D3–D4）        | matplotlib 画实时波形/频谱图         | ★☆ 半天    | 可先看现成工具，但训练后画混淆矩阵仍需                     |
| 数据集切窗 + 特征（D6–D7） | numpy 切窗、算特征、保存 npz          | ★★ 半天    | **否**（与固件同源的关键环节）                       |
| 模型训练（D7–D8）       | scikit-learn / PyTorch 训练与评估 | ★★★ 1 天  | 可换 Edge Impulse 网页版训练（代价：自定义度低、简历含金量略降） |
| 量化导出（D8）          | 转 ONNX/TFLite 脚本             | ★ 照抄示例即可 | 否，但基本是"抄官方示例改路径"                        |

**最小学习路线（D1 花 3–4 小时，之后按需查资料）**：

1. **语法速成**：变量/类型、if、for/while、函数、列表与字典、字符串、文件读写 —— 约 2 h（菜鸟教程或廖雪峰教程前 1/3 即可）；
2. **numpy**：数组创建/索引/切片/简单运算/reshape —— 1 h（本项目所有数据都是数组）；
3. **matplotlib**：画一条曲线、两幅子图（波形 + 频谱）—— 0.5 h；
4. **pyserial**：打开串口、读 N 字节、打印/存盘 —— 0.5 h；
5. **明确不学**：类与面向对象、装饰器、多线程、pandas、爬虫、Web——本项目用不到，先跳过。

> 配合方式：本项目所有 `tools/*.py` 脚本可以交给 AI 助手**逐段讲解并带你改写**；你的目标是"能读懂 + 能改参数"，不必追求独立从零写出。

### 3.2 Python 学习全流程
