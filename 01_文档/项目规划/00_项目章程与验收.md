# 项目章程与验收


## 1. 当前状态与维护边界

- 当前实现状态以[当前状态](../../知识库/10_当前状态.md)为准：已实现 1 kHz 采样、1024 点双缓冲、真实 MPU6050、串口帧与板上 Hann/RFFT/TOP-5 峰值；特征、模型、UI、报警和正式数据采集尚未完成。
- 三类为正常、不平衡、安装固定处机械松动；schema v3 固定 X 为测量轴、Y 为重力轴。轴承异常不在范围内。
- 原验收表的 425 us 只是历史阶段结果，不能作为当前 FFT+推理性能；当前尚无推理实现。

## 3. 项目概述

**一句话项目名（简历用）**：低成本边缘端电机振动故障检测系统（STM32 + TinyML）

**核心闭环**：

```text
  MPU6050 加速度计 ──I2C(DMA/FIFO)──> 连续采样(1 kHz)
        │
        ▼
  滑动窗口(1 s / 1024 点) ──加窗──> FFT 频谱 (CMSIS-DSP)
        │
        ▼
   特征提取（转速基频峰 1×、2×、分频段能量、峭度…）
        │
        ▼
  本地 AI 推理（轻量 MLP 或 1D-CNN，int8 量化）
        │
        ▼
   决策平滑（滞回 + 多窗投票）──> 4.3″屏显示状态/频谱 + 蜂鸣器/继电器报警
```

**为什么选这个项目（写给自己的理由，面试也常问）**：

- 覆盖嵌入式三大主线：**外设驱动**（I2C/中断/DMA/定时器/GPIO）、**信号处理**（FFT/加窗/特征工程）、**MCU 上的 AI 落地**（模型量化部署），每一环都能在简历和面试里单独展开；
- 闭环完整、可演示：传感器 → 算法 → 执行器，观众 30 秒内看懂；
- 成本可控：探索者板（含屏约 ¥250）+ 模块物料合计约 ¥300–400 级，在家即可完成；
- “离线 / 实时 / 低延迟 / 解决巡检痛点”正是工业现场的真实诉求，**立意好讲**，但必须用真实数据和实测指标支撑，不能只停留在口号（见 相关页面 诚信提醒）。

**最终成果物清单（做完的项目长这样）**：

1. 可现场演示的硬件样机（固定在一台风扇上，演示时用 12V 直流小风扇最安全可控）；
2. 1–2 分钟演示视频：正常 → 贴片制造不平衡 → 恢复 → 回退指定安装紧固点制造机械松动 → 屏幕显示对应状态并报警 → 重新紧固后恢复正常；
3. GitHub 仓库：README + 接线图 + 固件源码 + 数据采集与训练脚本 + 数据集样本 + 实测指标表；
4. 简历「项目经历」段落 + 一页答辩提纲 + 常见追问 Q&A（相关页面 已有模板）；
5. 本文档中的「待实测参数表」全部用**真实测量值**填满。

## 4. 目标与验收

### 4.1 目标

- 用 MPU6050 采集电机/风扇外壳振动，在 STM32 **本地离线**实时判断 **3 种状态：正常 / 不平衡 / 机械松动**；机械松动特指风扇与实验底座之间的安装固定处异常；
- 决策结果本地输出：4.3″ 触摸屏显示 + 蜂鸣器 + 继电器（演示联动断开负载）；
- 数据可回放：原始波形/频谱通过板载串口（CH340）上传 PC，用于建数据集与验证算法；
- 全链路资源可控：RAM/Flash 占用、推理耗时、端到端报警延迟均有**实测记录**（简历数据来源）。

### 4.2 验收指标

| 指标                 | 目标值                               | 实测值（待回填） | 测量方法                        |
| ------------------ | --------------------------------- | -------- | --------------------------- |
| 单帧（1024 点）FFT+推理耗时 | < 10 ms                           | 425 us   | 示波器测 GPIO 包络脉宽，或 DWT 周期计数打印 |
| 端到端报警延迟（故障出现→报警动作） | ≤ 1.5 s                           | ？        | 视频逐帧或示波器双通道（故障注入与报警沿）       |
| 状态刷新周期             | ≤ 1 s                             | ？        | 连续观测屏幕状态变化                  |
| 正常态连续误报            | 10 min 内 0 次                      | ？        | 计时观测                        |
| 异常检出（人为注入后）        | ≥ 95% 窗口判对                        | ？        | 留出测试集统计                     |
| 模型 ROM / 运行 RAM    | 目标 < 64 KB / < 32 KB              | ？        | 编译 map 文件 + 运行时统计           |
| 预算控制               | 整机（含开发板）≤ ¥500（已确认）；板外模块约 ¥60–160 | ✓ 已确认    | 采购清单合计                      |

> ⚠️ 指标只有**真实测量**才能写进简历；面试官 100% 会追问“这个 XXms 怎么测的、什么条件下测的”。相关页面 会给每项指标配“如何答辩”。

### 4.3 首版范围

- ✅ 裸机（或裸机+简单状态机）即可，**不必第一版就上 FreeRTOS**（可作为进阶项，见 相关页面）；
- ✅ 采样率 1 kHz，分析频带约 0–400 Hz（受 MPU6050 带宽限制，见 相关页面 的诚实说明）；
- ✅ 类别定为 **3 类：正常 / 不平衡 / 机械松动**（已选方案；标签与命名说明见 相关页面）；轴承异常不作为主类或扩展类保留；
- ✅ 主控用**探索者 STM32F407ZGT6**（已决策）；
- ❌ 不做云端、不做无线（BLE/WiFi 留作扩展）、不追求真实产线部署（强调"演示级原理验证 + 有向工业迁移的明确路径"即可）。

### 4.4 标签体系

- **模型标签为 3 类**：`normal / unbalance / looseness`，另保留 `unassigned` 表示尚未能用于训练的样本。
- **标签拆成四层**：`observed_condition` 记录客观工况（`baseline`、`added_mass`、`mount_looseness`、`unknown`）；`target_label` 记录模型类别；`label_basis` 记录依据；`label_confidence` 记录 `confirmed / suspect / unknown`。默认映射为 `baseline → normal`、`added_mass → unbalance`、`mount_looseness → looseness`。
- **机械松动的口径**：只改变风扇与刚性底板之间的指定安装紧固点，记录 `loose_fastener_id` 以及 `loosen_turns` 或 `mount_gap_mm`；底板与桌面始终夹紧。整机滑移、软垫晃动、叶片擦碰不算合格的松动样本。
- **版本边界**：本次类别变化把数据契约升级为 schema v3；schema v1/v2 历史文件保持不变，不改标签、不与 v3 正式数据混合训练。
- **固定轴向**：`measurement_axis=X` 为振动测量轴，`gravity_axis=Y` 为重力轴。这个轴向会写入每个文件头，旧数据缺少该字段时按 legacy 处理，不追写旧文件。
- **采集表单明确不记录**：夹具版本、传感器编号、传感器安装点。这些不作为模型标签或必填元数据；实际测量时仍须保持安装方式稳定，并在 `notes` 中记录会影响解释的临时情况。
