# 总体方案与数据流


## 1. 当前实现边界

当前链路是 MPU6050 → 软件 IIC（PB6/PB7）→ app_sample.c（TIM3、1 kHz、1024 点、X 轴）→ dsp_fft.c（去均值、Hann、RFFT）→ link_frame.c → USART1（460800）→ recv.py。特征、分类、平滑决策、屏幕和报警仍是设计项；详情见[系统地图](../../知识库/20_系统地图.md)。


## 2. 处理流程

### 2.1 数据处理流水线

| 环节     | 参数草案                                | 说明                               |
| ------ | ----------------------------------- | -------------------------------- |
| 采样率 fs | 1000 Hz（ODR 1 kHz）                  | 加速度计轴：选振动最强的径向轴（如 Y 轴），可同时记录三轴备用 |
| 量程     | ±2 g（16 bit → ~0.061 mg/LSB）        | 风扇振动量级小，±2 g 分辨率最高               |
| 窗口     | 1024 点 = 1.024 s                    | 重叠 50%，即约每 0.5 s 出一个决策           |
| 窗函数    | Hann                                | 降低泄漏                             |
| FFT    | CMSIS-DSP `arm_rfft_fast_f32`(1024) | F407（M4F）上毫秒级                    |
| 特征     | 约 10–16 维（见 相关页面）                   | 由固件算或用 Python 同参数离线算（两者必须一致！）    |
| 分类     | MLP(特征→3 类) 起步；1D-CNN(频谱→3 类) 进阶    | 部署走 X-CUBE-AI                    |
| 决策平滑   | 最近 5 窗投票或概率 EMA + 滞回阈值              | 防抖动误报                            |
| 报警     | 连续 K 窗异常才动作；正常连续 M 窗才复位（或按键复位）      | 工业上叫"防抖/滞回"                      |

### 2.2 特征设计

1. 估计 f0（1× 转速，Hz）；
2. A(f0)/总能量（不平衡指示，最重要）；
3. A(2×f0)/A(f0)（不对中/松动指示）；
4. 低频段能量占比（0–50 Hz）；
5. 中频段能量占比（50–200 Hz）；
6. 高频段能量占比（200–400 Hz）（保留作冲击/宽带变化描述，不单独对应某一类别）；
7. 总 RMS；
8. 时域峭度（Kurtosis，对冲击敏感）；
9. 峰值因子（Crest Factor）；
10. 0.5×f0、2×、3× 能量及谐波丰富度（机械松动指示，可按数据消融筛选）。

> 训练与部署的**特征算法必须同源**：Python 离线算特征的脚本与固件实现用同一组参数（窗长、窗型、频段切分、归一化），否则"训练 98% / 板子上 60%"就是这么来的（train–serve skew）。

### 2.3 运行架构

```text
[中断层]
  I2C FIFO 水印中断 / SysTick 调度心跳
        │
[数据层]  环形/乒乓缓冲：DMA 搬运，双缓冲轮流
        │
[处理层]  主循环或低优先级任务：取满 1024 点 → 加窗 FFT → 特征 → 推理 → 平滑决策
        │
[输出层]  屏幕刷新(≈10 Hz)、蜂鸣器/继电器状态机、串口日志
```

- 采样与决策解耦：DMA 后台不间断采，主循环按窗消费——天然避免"推理时丢样本"；
- 推理等长运算**不进中断**，放主循环/低优先级，防止阻塞采样；
- 状态机：`IDLE → ACQUIRING → CLASSIFY → ALARM_CONFIRM / NORMAL`，各状态带超时保护。
