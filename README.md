# 电机振动故障检测

一个以 **STM32 + MPU6050** 为采集端、以 **Python** 为分析与数据管理端的电机/风扇振动检测项目。

项目围绕低速小型直流风扇，建立从传感器采样、频谱分析、串口传输、数据质量检查，到后续**轻量模型**训练与**边缘部署**的完整技术链路。当前模型标签契约聚焦于三类可控工况：**正常、不平衡、安装固定处机械松动**。

项目的核心目标不是只输出一张频谱图，而是把“机械故障机理、嵌入式实时处理、PC 数据管线和可复现实验”连接成一套可以继续扩展的工程骨架。

## 项目亮点

- **端侧实时信号处理**：STM32 以 1 kHz 定时采样，使用 1024 点双缓冲窗口，在板上完成去均值、Hann 窗、CMSIS-DSP 实数 FFT、单边幅值谱和 TOP-5 峰值提取。
- **物理可解释的检测思路**：以转频 1×、2×/3× 谐波、频带能量和幅值变化作为分析线索，优先使用加速度频谱，而不是直接依赖难以解释的原始时域波形。
- **固件与 PC 端同口径对拍**：板上 FFT 和 Python 检查脚本共享采样率、窗口长度、轴向、加窗和峰值搜索范围，可用同一窗口核对 bin、频率和幅值。
- **从原始字节到数据集的完整链路**：固件通过 USART1 发送带窗口序号、采样点数和量程信息的原始数据帧，Python 端负责拆帧、落盘、元数据校验、质量状态管理和 manifest 生成。
- **结构化标签契约**：schema v3 将客观工况、模型标签、标签依据、可信度和机械松动量化字段分开保存，避免把“人为注入条件”和“模型类别”混成一个字符串。
- **面向跨设备验证**：数据集设计保留 `device_id`、`session_id` 等字段，训练清单按设备留出测试集，降低同一台风扇相邻窗口泄漏带来的虚高准确率。
- **问题记录可复用**：传感器异常、软件 IIC 总线冲突、串口 DTR/RTS 复位、频谱选择和故障标签调整均保留了现象、证据、根因和验证方法，方便复盘与二次开发。

## 技术路线

### 1. 机械对象与传感器安装

被测对象为低转速小型直流风扇。MPU6050 刚性耦合到风扇外壳或测量夹具，当前数据契约固定 **X 轴为振动测量轴，Y 轴为重力参考轴**。实验通过添加质量模拟不平衡，通过指定安装紧固点的回退圈数或间隙模拟安装固定处机械松动。

硬件平台、接线、电源和传感器安装纪律见 [硬件方案、接线与采购](01_文档/项目规划/03_硬件方案_接线与采购.md)。

### 2. STM32 采样与窗口管理

- 主控方向：STM32F407ZGT6，Cortex-M4F，168 MHz，使用 STM32 HAL、CMSIS 和 CMSIS-DSP。
- 传感器接口：软件 IIC，SCL=`PB6`、SDA=`PB7`，加速度量程为 ±2 g。
- 定时采样：TIM3 产生 1 kHz 采样节拍。
- 缓冲策略：1024 点窗口、双缓冲、采样与处理解耦；窗口完成后携带递增序号交给处理层。
- 数据源：支持真实 MPU6050 数据，也保留合成信号入口用于 DSP 自检。

主要入口位于 [`00_工程文件/APP/app_config.h`](00_工程文件/APP/app_config.h)、[`app_sample.c`](00_工程文件/APP/app_sample.c) 和 [`mpu6050.c`](00_工程文件/Drivers/BSP/MPU6050/mpu6050.c)。

### 3. 板上频谱分析

每个窗口按照下面的顺序处理：

```text
int16 原始加速度
      ↓
量程换算为 g
      ↓
计算均值并去直流
      ↓
乘 Hann 窗
      ↓
CMSIS-DSP arm_rfft_fast_f32
      ↓
单边幅值谱
      ↓
10～400 Hz 搜索 TOP-5 峰值
```

当前参数为 `fs = 1000 Hz`、`N = 1024`，频率分辨率约为 **0.9766 Hz/bin**。板上通过 DWT 周期计数记录 FFT 处理耗时，并以 ASCII 文本日志输出均值、峰值 bin、频率和幅值，便于与 PC 端结果对拍。

DSP 实现见 [`dsp_fft.c`](00_工程文件/APP/dsp_fft.c) 与 [`dsp_fft.h`](00_工程文件/APP/dsp_fft.h)；历史对拍口径见 [D4 板上 FFT 集成与对拍记录](01_文档/技术实施/历史验证/D4_板上FFT集成与对拍记录.md)。

### 4. 串口链路与 PC 解析

USART1 当前配置为 **460800 baud**。一帧原始加速度数据包含帧头、帧类型、轴标识、窗口序号、样本数、量程代码和 little-endian `int16` 样本；1024 点窗口的帧长度为 2057 字节。文本日志使用同一帧头体系，方便串口接收端区分数据帧和日志帧。

固件封装见 [`link_frame.c`](00_工程文件/APP/link_frame.c) / [`link_frame.h`](00_工程文件/APP/link_frame.h)，PC 端对应解析见 [`frames.py`](03_Python工具/py_common/frames.py)。两端的帧格式是通信契约，修改时必须同步验证。

### 5. 数据集与标签契约

Python 侧将数据分成三种使用层次：

1. **debug**：调试串口、传感器和算法，不直接进入训练集；
2. **formal**：按结构化元数据采集、检查并登记的正式原始数据；
3. **processed**：从通过质检的 formal 数据生成的训练/测试清单。

默认工况映射为：

| 客观工况 | 模型标签 | 说明 |
| --- | --- | --- |
| `baseline` | `normal` | 正常运行基线 |
| `added_mass` | `unbalance` | 受控添加质量，模拟转子不平衡 |
| `mount_looseness` | `looseness` | 指定安装点受控松动 |

数据契约、字段解释和历史 schema 兼容规则见 [数据集目录与标签契约](04_数据集/README.md)；操作命令见 [采集操作手册](04_数据集/采集操作手册.md)；唯一配置源见 [`config.json`](03_Python工具/config.json)。

### 6. 特征、训练与边缘部署

完整路线预留两种模型输入：

- **特征路线**：从基频、1×/2×峰值关系、谐波丰富度、频带能量、RMS、峭度等统计量构造小维度特征，训练轻量 MLP 或其他浅模型；
- **频谱路线**：使用 0～400 Hz 的对数幅度谱训练 1D-CNN，在数据量和算力允许时提高表达能力。

两条路线都遵循“按设备划分数据 → PC 端 float32 验证 → int8 量化 → ONNX/TFLite 导出 → X-CUBE-AI 生成 C 网络 → 板上 DWT/Map 文件核对资源”的流程。模型训练与部署设计见 [模型训练与边缘部署](01_文档/项目规划/05_模型训练与边缘部署.md)，显示、报警和交互路线见 [显示、报警与交互](01_文档/项目规划/06_显示报警与交互.md)。

## 工程边界与可信度说明

本项目面向低速小型风扇，当前频谱链路重点覆盖约 10～400 Hz 的低阶转频、谐波和结构响应，不覆盖高频冲击型轴承故障。机械松动指风扇与实验底座之间的受控安装异常，不等同于所有工业场景中的松动。任何模型准确率、跨设备泛化能力和板上资源占用，都应以可追溯的数据、日志、混淆矩阵和 map 文件为依据。

如果需要查看工程维护口径，再进入 [当前状态](知识库/10_当前状态.md)；它是状态信息入口，不替代源码、配置、数据和实验记录本身。
